A lightweight in-memory database engine for learning and building collection-based storage, schema validation, hash indexing, and JSON persistence.

Introduction

AetherCache is a compact database project built to explore internal database concepts: collection storage, record identity, schema validation, primary-key indexing, and persistence. It is intentionally small, readable, and designed for experimentation.

storage

In-memory storage

Collections and records live in memory for fast local access and simple engine behavior.

schema

Schema validation

Each collection owns a schema, keeping validation aligned with table-style boundaries.

index

Hash indexing

Primary-key indexes provide direct hash-map lookup while leaving room for secondary indexes.

disk

JSON persistence

Database state can be serialized to local JSON without coupling indexes to disk format.

types

TypeScript support

The engine uses TypeScript interfaces for collections, records, schemas, and indexes.

embedded

Embedded architecture

Use the database directly in a Node.js process without running a separate server.

Installation

Install the package, then import the database class from your TypeScript or JavaScript project.

terminal 
npm install aether-cache
AetherCache is designed as a learning-friendly embedded database. Keep it close to your app logic, then evolve the storage, indexing, and query layers as the project grows.

Quick Start

Create a database instance, define a collection schema, insert records, and retrieve them by primary key.

quick-start.ts 
import { microDB } from "aether-cache";

const db = new microDB<{
  name: string;
  age: number;
  email: string;
}>();

db.createCollection("users", {
  name: "string",
  age: "number",
  email: "string",
});

const id = db.insert("users", {
  name: "Ada Lovelace",
  age: 36,
  email: "ada@example.com",
});

const user = db.get("users", id as string);
console.log(user?.data);

Collections

Collections are the main boundary in AetherCache. A collection owns its schema, records, metadata, and index definitions.

Collection metadata

Each collection tracks creation time, update time, and record count for lightweight introspection.

Schema association

Schemas belong to collections, which keeps validation separate from record identity.

collections.ts 
db.createCollection("sessions", {
  token: "string",
  expiresAt: "number",
});

const collection = db.getCollection("sessions");
console.log(collection.metadata.recordCount);

CRUD Operations

Records are collection-scoped and addressed by primary key. IDs can be generated automatically or supplied explicitly for deterministic workflows.

crud.ts 
// Create
const id = db.insert("users", {
  name: "Grace Hopper",
  age: 85,
  email: "grace@example.com",
});

// Read
const record = db.get("users", id as string);

// Update
db.update("users", id as string, {
  name: "Grace Hopper",
  age: 86,
  email: "grace@example.com",
});

// Delete
db.delete("users", id as string);

Indexing

AetherCache maintains a hash-based primary-key index per collection. The live index stores references to records, enabling direct lookup without scanning the full collection.

  • Primary-key lookup is collection-scoped.
  • Indexes synchronize on insert, update, and delete.
  • Index metadata stays on the collection; live hash maps stay inside the index manager.
  • Secondary indexes can later use the same manager boundary.
indexing.ts 
const record = db.indexManager.getByPrimaryKey(
  "users",
  id as string
);

console.log(record?.identity.primaryKey);

Persistence

Persistence is JSON-based and intentionally simple. Stored data includes collections, schemas, records, metadata, and lightweight index definitions. Live index hash maps can be rebuilt from records.

This keeps persistence readable and avoids tying disk format to in-memory indexing details.
initialize.ts 
const db = new microDB();
await db.initialize();

// Collections are loaded from disk and indexes are rebuilt in memory.

API Reference

A concise map of the core developer-facing methods.

createCollection

db.createCollection(name, schema, metadata?)

Create a collection with schema, metadata, records, and index definitions.

deleteCollection

db.deleteCollection(name)

Remove a collection and drop its live indexes.

insert

db.insert(collection, value, id?)

Validate and insert a record, returning the primary key or false.

get

db.get(collection, id)

Read a record using the collection primary-key index.

update

db.update(collection, id, value)

Validate, replace record data, and synchronize the primary index.

delete

db.delete(collection, id)

Delete a record from storage and remove it from the index.

Future Roadmap

AetherCache is intentionally modular so new database internals can be added without replacing the collection and record foundation.

  • Secondary indexes for fields beyond primary key.
  • Query engine integration over collections and indexes.
  • Range queries and basic query planning.
  • Transaction and concurrency experiments.
  • Persistence compaction and recovery strategies.
